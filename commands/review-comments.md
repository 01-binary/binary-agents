# PR 리뷰 코멘트 분석기

현재 브랜치에 열린 PR의 리뷰 코멘트를 가져와서, 각 코멘트가 실제로 개선이 필요한지 판단하고, 필요하다면 구체적인 변경 방법을 제시합니다.

## 컨텍스트 정보

**현재 브랜치:**
!`git rev-parse --abbrev-ref HEAD`

**현재 브랜치의 PR 정보:**
!`gh pr view --json number,title,state,author,url,reviewDecision,reviews 2>/dev/null || echo "PR을 찾을 수 없습니다"`

**PR 리뷰 코멘트 (라인별):**
!`gh pr view --json number --jq '.number' 2>/dev/null | xargs -I{} gh api --hostname "$(git remote get-url origin 2>/dev/null | sed -E 's#^[^@/]+@([^:]+):.*#\1#; s#^https?://([^/]+)/.*#\1#')" repos/:owner/:repo/pulls/{}/comments --jq '.[] | "---\n작성자: \(.user.login)\n파일: \(.path):\(.line // .original_line // "N/A")\n상태: \(.position // "outdated")\n내용: \(.body)\n"' 2>/dev/null || echo "리뷰 코멘트 없음"`

**PR 일반 코멘트:**
!`gh pr view --json comments --jq '.comments[] | "---\n작성자: \(.author.login)\n내용: \(.body)\n"' 2>/dev/null || echo "일반 코멘트 없음"`

**PR 리뷰 요약:**
!`gh pr view --json reviews --jq '.reviews[] | "---\n작성자: \(.author.login)\n상태: \(.state)\n내용: \(.body)\n"' 2>/dev/null || echo "리뷰 요약 없음"`

## 작업 순서

1. **PR 존재 확인**
   - 현재 브랜치에 열린 PR이 있는지 확인
   - PR이 없으면 사용자에게 안내하고 종료
   - PR이 있으면 번호, 제목, 리뷰 상태 표시

2. **코멘트 수집 및 분류**

   GitHub PR에는 3가지 유형의 코멘트가 존재:

   | 유형 | API | 설명 |
   |------|-----|------|
   | **Review comments** | `pulls/{number}/comments` | 특정 코드 라인에 달린 코멘트 (가장 중요) |
   | **Issue comments** | PR의 `comments` 필드 | PR 전체에 대한 일반 코멘트 |
   | **Review summaries** | PR의 `reviews` 필드 | 리뷰 승인/변경요청 시 남긴 요약 |

   모든 유형을 수집하되, **Review comments (라인별 코멘트)** 를 우선 분석

3. **각 코멘트 분석**

   각 코멘트에 대해 다음을 판단:

   - **코멘트가 가리키는 파일과 라인**을 `Read`로 읽어서 현재 코드 상태 확인
   - 코멘트의 의도 파악 (버그 지적, 개선 제안, 질문, 칭찬, 스타일 의견 등)
   - **이미 해결되었는지** 확인 (코드가 이미 수정된 경우)
   - 코멘트가 유효한 개선점인지 판단

4. **코멘트 분류**

   각 코멘트를 다음 중 하나로 분류:

   | 분류 | 기준 |
   |------|------|
   | 🔴 **개선 필요** | 버그, 보안 이슈, 명확한 코드 품질 문제 지적. 코드 변경이 필요함 |
   | 🟡 **논의 필요** | 설계 방향, 트레이드오프가 있는 제안. 판단이 필요함 |
   | 🟢 **조치 불필요** | 칭찬, 단순 질문, 이미 해결됨, 스타일 취향 차이 |

5. **개선 방법 제시**

   🔴, 🟡로 분류된 항목에 대해:
   - **왜** 바꿔야 하는지 (코멘트 작성자의 의도 + 기술적 근거)
   - **어떻게** 바꿔야 하는지 (구체적인 코드 변경 방향 제시)
   - 필요하면 관련 파일을 `Read`로 읽어 전체 맥락 파악

## 출력 형식

```markdown
# PR 리뷰 코멘트 분석

## PR 정보
- **제목:** [PR 제목]
- **번호:** #[number]
- **URL:** [PR URL]
- **리뷰 상태:** [APPROVED / CHANGES_REQUESTED / REVIEW_REQUIRED]
- **총 코멘트:** N개

---

## 분석 요약

| 분류 | 개수 |
|------|------|
| 🔴 개선 필요 | X |
| 🟡 논의 필요 | Y |
| 🟢 조치 불필요 | Z |

---

## 🔴 개선 필요

### 1. [코멘트 요약]
- **작성자:** @[author]
- **위치:** `file/path.ts:42`
- **원본 코멘트:** > [코멘트 내용]

**왜 바꿔야 하는가:**
[기술적 근거와 코멘트 작성자의 의도 설명]

**어떻게 바꿔야 하는가:**
현재 코드:
```[lang]
// 현재 코드
```

제안하는 변경:
```[lang]
// 변경된 코드
```

---

## 🟡 논의 필요

### 1. [코멘트 요약]
- **작성자:** @[author]
- **위치:** `file/path.ts:15`
- **원본 코멘트:** > [코멘트 내용]

**코멘트 분석:**
[코멘트가 제안하는 방향과 현재 코드의 트레이드오프 설명]

**선택지:**
- A: [코멘트대로 변경하는 경우 장단점]
- B: [현재 코드를 유지하는 경우 근거]

---

## 🟢 조치 불필요

| 작성자 | 위치 | 내용 요약 | 사유 |
|--------|------|-----------|------|
| @user | `file.ts:10` | 좋은 패턴 칭찬 | 칭찬 |
| @user | `file.ts:25` | 변수명 질문 | 이미 답변됨 |

---

## 다음 단계

1. 🔴 항목부터 순서대로 수정
2. 🟡 항목은 팀과 논의 후 결정
3. 수정 완료 후 re-review 요청
```

## 에러 처리

- **PR 없음:** "현재 브랜치에 열린 PR이 없습니다. 먼저 PR을 생성해주세요."
- **코멘트 없음:** "이 PR에 리뷰 코멘트가 없습니다. 리뷰를 요청해보세요."
- **GitHub CLI 미인증:** `gh auth login` 실행 안내
- **outdated 코멘트:** 코드가 이미 변경되어 라인이 맞지 않는 경우, 최선을 다해 현재 코드에서 해당 위치를 찾아 분석

## 중요 사항

- **현재 코드 기준 판단** - 코멘트가 달린 시점이 아닌, 현재 코드 상태를 기준으로 이미 해결되었는지 확인
- **맥락 파악** - 코멘트가 가리키는 파일을 반드시 `Read`로 읽어서 전체 맥락 안에서 판단
- **객관적 분류** - 개인 취향 vs 실제 문제를 구분. 근거가 약한 의견은 🟡로 분류
- **한국어 출력** - 최종 리포트는 한국어로
- **코드 변경은 하지 않음** - 분석과 제안만 제공, 실제 코드 수정은 사용자가 별도 요청 시 수행
